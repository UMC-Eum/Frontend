1. 백엔드 담당

운영 데이터, 계정 삭제, UGC 안전장치와 심사용 production 상태를 책임집니다.

Backend
BE-1 · 배포 차단

운영 약관 데이터 등록

PM이 확정한 원문을 production DB에 등록합니다. 앱은 동적 조회하므로 데이터 등록만으로 반영되며 재빌드는 필요 없습니다.

완료 증빙: 약관 API 응답과 신규 계정 온보딩 성공 화면
BE-2 · 배포 차단

회원탈퇴가 실제 삭제를 보장하는지 확인

현재 앱은 PATCH /api/v1/users/me/deactivate를 호출합니다. 단순 휴면이 아니라 삭제 또는 삭제 예약이어야 합니다.

완료 증빙: 테스트 계정 탈퇴 결과와 데이터 보관/삭제 정책
BE-3 · 추가 심사 위험

UGC 필터링과 신고 운영 체계

신고·차단 UI는 확인됐지만 Apple은 게시 전 필터링과 운영 대응도 요구합니다. 기존 시스템이 있으면 새로 만들지 말고 작동 증거만 제출합니다.

적용 대상

  • 프로필 닉네임·소개
  • 채팅 텍스트·사진·음성
  • 동호회 이름·설명
  • 게시글·댓글·첨부 이미지
BE-4 · 운영 준비

Production 핵심 경로와 심사용 데이터

2. 프론트엔드 담당

최종 코드, 공개 링크, EAS Build 16과 실제 바이너리 스모크를 책임집니다.

Frontend
FE-1 · 코드 마감

남은 코드 반영

chore/EUM-133-ios-appstore-release / 기준 a73b1bb. 현재 원격보다 2커밋 앞서고 axios timeout 수정이 미커밋 상태입니다.

FE-2 · Git/검증

PR과 재현 가능한 소스

pnpm install --frozen-lockfile

pnpm dlx expo-doctor
pnpm lint

현재 허용 결과: lint 오류 0, 기존 경고 3건.

FE-3 · EAS Build 16

production 환경 확인 후 생성·업로드

pnpm dlx eas-cli env:list production --format long
pnpm dlx eas-cli build:version:get --platform ios --profile production --non-interactive

pnpm dlx eas-cli build \
  --platform ios \
  --profile production \
  --auto-submit \
  --message "App Store release 1.1.0 (16)" \
  --wait

4. 실제 배포 순서

선행 조건을 지켜야 재빌드와 심사 반려를 피할 수 있습니다.

Release Owner

백엔드·PM 차단 항목 완료

약관, 탈퇴, UGC, 공개 페이지, 데모 계정을 먼저 끝냅니다.

프론트 URL 연결·코드 병합

릴리스 브랜치 push, dev PR 병합, clean worktree를 확인합니다.

Build 16 생성·자동 업로드

EAS Build와 Submission이 모두 FINISHED인지 확인합니다.

Build 16 실기기 스모크

내부 TestFlight 한 회로 설치·인증·온보딩·핵심 기능을 확인합니다.

App Store Connect 완성

메타데이터, App Privacy, 연령 등급, 규정, Review Information을 채웁니다.

Add for Review → Submit for Review

Build 16을 선택하고 Draft Submissions에서 실제 심사를 제출합니다.

심사 대응

Waiting for Review → In Review를 모니터링하고 메시지에 즉시 답합니다.

수동 출시

Pending Developer Release에서 Release This Version을 누릅니다.

실제 노출 확인

App Store 검색·설치·로그인을 확인하고 EUM-133을 닫습니다.
