검증 완료
1회독 · 기술 파이프라인

저장소 → EAS → 번들

  • app.json 패키지명과 google-services.json 일치
  • Expo SDK 54 기본 target SDK 36으로 현재 Play 최소 API 35 충족
  • EAS production 원격 versionCode 1, autoIncrement: true → 다음 2
  • 운영 API /api 포함, WebSocket 운영 주소가 Android 번들에 포함
  • Google Play 제출용 AAB 이력은 0건, 과거 preview APK만 2건
  • Expo prebuild 매니페스트에서 READ_MEDIA_IMAGES/VIDEO 미선언 및 미사용 특수 권한 제거 지시 확인
검증: TypeScript, lint, Expo Doctor 18/18, Android production export, EAS build/version 조회
2회독 · 정책과 운영

Google Play → 실제 서비스

  • Dating 앱: Play Console에서 18+만 선택하고 Restrict minor access 활성화 필수
  • Social/Dating 앱: 공개 CSAE 금지 기준, 신고 채널, CSAM 대응, 아동 안전 담당자 필수
  • UGC: 약관 동의, 금지행위 명시, 신고·차단뿐 아니라 실제 검토·조치 운영 필요
  • 계정 생성 앱: 앱 내 탈퇴와 앱 밖에서 요청 가능한 공개 삭제 URL 모두 필요
  • Data safety, 개인정보처리방침, 앱 접근용 심사 계정, 콘텐츠 등급 필수
  • 팀 계정은 Organization이므로 개인 계정 대상 12명·14일 closed test 의무는 적용되지 않음
  • 대신 D-U-N-S·조직 문서·담당자 신원·이메일·전화·웹사이트 검증 상태 확인 필수
교차결론: 코드 컴파일은 가능하지만 운영·정책·AAB가 미완료이므로 현재 정식 제출은 NO-GO

실제 배포 순서

위에서 아래로 한 번만 진행합니다.

Release Owner

백엔드와 공개 웹 차단 해소

운영 약관 1~3, 실제 계정삭제, UGC/CSAE 운영, privacy·terms·support·delete-account URL을 완료합니다.

Play Console 앱과 정책 설정

패키지 com.eumdating.app로 앱을 만들고 App content, 18+, Restrict minor access, Data safety, App access를 완료합니다. 패키지명은 생성 후 변경할 수 없습니다.

최종 소스 병합·고정

이슈 #189 기준 PR을 병합하고 clean release branch의 HEAD SHA를 기록합니다.

production AAB 생성

eas build --platform android --profile production으로 예상 1.1.0 (2)를 생성합니다.

내부 또는 closed track 업로드

Play App Signing을 활성화하고 AAB를 업로드합니다. Organization 계정이므로 12명·14일 의무 없이 내부 검증 후 production으로 진행할 수 있습니다.

Google 자동 검사와 실기기 확인

Pre-launch report, 권한·Data safety 경고, Android vitals, 기기 호환성을 확인하고 AAB 설치본으로 스모크 테스트합니다.

Production release 생성

릴리스 노트 작성, 국가·가격·출시 방식과 Managed publishing 여부를 확정하고 Review release에서 오류가 0인지 확인합니다.

심사 제출 → 승인 → 출시

Send for review 후 정책 메일과 Console 상태를 추적합니다. 승인 뒤 Publish 또는 예약된 Managed publishing으로 공개합니다.

출시 직후 모니터링

Play 설치본의 로그인·API·FCM·채팅을 재확인하고 Android vitals의 crash/ANR 및 운영 신고 큐를 모니터링합니다.
